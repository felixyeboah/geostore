Adding a product, three ways

Same fields, same data model, same editorial language as the rest of the admin. Each option answers the brief differently: make it obvious what to fill in, make variants understandable, and make it hard to publish something broken.

What the current sheet gets wrong

  1. A drawer for a 2,200 px form. Six sections and a variant matrix squeezed into a 640 px side panel. The table gets five cramped columns and the photo editor nests three levels deep.
  2. No hierarchy. Every label is the same grey small caps. Name and Compare-at price weigh the same; nothing says which fields are required.
  3. Order fights the mental model. Price and stock are asked before "does it come in options?" — then the matrix overrides them. Department, which is required, hides under "Publishing" at the bottom.
  4. Plumbing shown to everyone. URL slug and a raw image-URL textarea sit in the main flow.
  5. Variants are the hardest part and the least explained. Option name, chip input, quick-add, the expanded swatch/photo box and the matrix all live inside one bordered card, with no statement of what a "combination" is.
  6. No sense of progress. There is no "what's left before this can go live", so the only feedback is a failed save.

These are working prototypes

  • Every control works: type a name and watch the address, counts and readiness update; add and remove options and choices (Enter or comma adds, Backspace removes the last); the combinations table regenerates and keeps what you typed.
  • As soon as a Colour option has choices, a “Photos for each colour” block appears under it: one row per colour with its swatch, its own photo strip and an Add photos button. Clicking a colour chip jumps to its row. Hover any photo to make it the cover or remove it; "Add photos" opens a real file picker.
  • Switch between "one version" and "comes in options" without losing anything. Publish is gated by the readiness list; Discard empties the form so you can try it from blank; "Reload sample" (bottom-left) brings the Apple Watch back.
  • Product photos are generated packshots, so the pages read like a real catalogue rather than placeholder tiles.

Shared by all three

  • A full page, not a drawer. The list is one click back.
  • One explicit decision — "one version" or "comes in options" — and the price/stock UI changes to match.
  • Required fields marked; a readiness list gates Publish; Save draft is always available.
  • Photos for a colour are edited in a visible “Photos for each colour” block with one row per colour, never behind a hidden click.
  • Specifications as label/value rows, not a "Label: Value" textarea.
  • Slug shown as a read-only address with "change"; image URLs behind a link.

Guided page

One column, four numbered questions — What is it? · Photos · How is it sold? · Specifications — with a sticky rail that lists what is left before it can go live. The most conventional; the easiest to hand to someone new.

Workspace with live preview

3

Three steps

Describe it → Price it → Check and publish. One job per screen, so nothing is ever off-screen or out of order, and the last step is a plain-English review with "Edit" beside every block. The most hand-holding; slower for someone entering twenty products in a sitting.
